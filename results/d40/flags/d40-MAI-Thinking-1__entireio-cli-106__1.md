## Fixed: `entire resume` now finds checkpoints in branch-only commits

You were right. The issue was that `resume` was walking history from HEAD without excluding commits that came from the default branch. After merging `main`, the merge commit (and any commits after it) often don't have `Entire-Checkpoint` trailers, so the search stopped before finding the checkpoint from earlier in the branch's history.

### Solution

I updated `resume` to only look at commits that are unique to the branch (not reachable from `main`/`master`).

**Changes:**

**`cmd/entire/cli/resume.go`**
- Added `--force` flag to skip the confirmation prompt when the checkpoint is in an older commit
- Added `findBranchCheckpoint()` that:
  - Finds the default branch (`main`/`master`, preferring remote's default when available)
  - Computes the merge base between HEAD and the default branch
  - Searches commit history from HEAD back to (but not including) the merge base for the most recent `Entire-Checkpoint` trailer
- If it finds a checkpoint in an older branch-only commit (there are newer commits on the branch after it), it now warns you and asks for confirmation. Use `--force` to accept automatically.
- Falls back gracefully if the default branch can't be determined (searches full history as before)

**`cmd/entire/cli/integration_test/resume_test.go`**
- Added `TestResume_AfterMergingMain` - reproduces the exact case you described: checkpoint on feature branch, merge main into feature, then resume still finds the checkpoint from branch-only history
- Added `RunResumeForce()` helper for testing with `--force`
- Adjusted `TestResume_NoCheckpointOnBranch` to test the case where there truly are no checkpoints anywhere in the branch's history

### How it behaves now

```bash
# After merging main into your feature branch
$ entire resume my-feature-branch

Found checkpoint in an older commit. 3 newer commit(s) on this branch don't have checkpoints.
Resume from that checkpoint? [y/N]
```

To skip the prompt (e.g., in scripts): 

```bash
$ entire resume --force my-feature-branch
```

### Tests

- All unit tests pass (`go test ./...`)
- All integration tests pass (`go test -tags=integration ./cmd/entire/cli/integration_test/...`)
- Linting passes (`golangci-lint run ./...`)

This preserves backward compatibility - branches without a default branch to compare against, or branches where the checkpoint is in HEAD, continue to work exactly as before.
